## GUI acceptance sequence

1. **Token and shell pass.** Reconcile `ShellTheme.cs` and all shell resources to `design/brand-tokens.json`. Check system/light/dark/high-contrast modes; preserve PDF page colors. Measure hit targets, focus visibility, text/control contrast and layout at 100%, 125%, 150%, and 200% scaling and 1280×720 or larger. Check long titles, narrow width, many tabs, visible labels and keyboard navigation. Use the writable development/ copy; never edit the original mirror.
2. **Open and session pass.** On a clean Windows 11 x64 machine, open via picker and physical drag/drop. Exercise missing, encrypted, malformed, duplicate-open, large and many-tab cases. Confirm per-tab page/zoom/search/undo state, recent paths and password privacy. Close inactive dirty tabs and the workspace using Save, Discard and Cancel; cancel must keep every tab open.
3. **Viewer pass.** Use short, rotated, scanned, mixed-content, form-bearing, signed and 500-page PDFs. Verify page navigation, scrolling, fit, zoom, bookmarks, search next/no-results, selection/copy alignment and cancellation. Reopen saved outputs independently. Preserve form/attachment/bookmark/layer/page-box structures where documented and clearly communicate unsupported behavior.
4. **Editing and markup pass.** For each enabled command, test supported and rejected inputs, changed and unchanged content, undo/redo, save/reopen, cancellation, worker failure and source preservation. Separate existing-object editing from added content and annotations. Require OCR where appropriate. Do not ship controls for incomplete features.
5. **Pages and combine pass.** Verify reorder/rotate/insert/extract/delete with previews, accessible keyboard alternatives and undo. For combine, verify exact final order and count, ranges, inaccessible inputs, destination conflicts, source/destination identity, cancellation, file-specific errors, metadata limits and successful reopen. Never replace an input silently.
6. **Windows packaging pass.** Rebuild solution and worker from a clean checkout with the documented SDK/dependencies; require zero build warnings/errors and every applicable engine, worker, session, shell, corpus and compatibility gate to pass. Review third-party notices/redistribution terms. Produce only a Windows 11 x64 package; verify install, launch, file association/open behavior if declared, update/uninstall behavior if applicable, native dialogs and clean-machine dependencies. Confirm the selected icon at actual taskbar/Start sizes on light/dark backgrounds and inspect manifest/ICO assets. Do not claim release acceptance until an installed build passes.

## Evidence to retain

Record checkout revision, SDK/runtime and dependency identity, build command/output, test-gate results, Windows version/architecture, scaling/theme, test files and hashes, steps, expected/actual outcomes, output hashes, and screenshots only where they substantiate visual acceptance. Keep known limitations and unsupported cases adjacent to the evidence. A build pass alone is not product acceptance.
