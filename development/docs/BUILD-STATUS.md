## October 21, 2026 — on-page editing of embedded-font and tagged text (source only; no new package)

User testing of the Edit toolbar on a real document found that only text added in this app could be edited. The cause: the built-in PDFium editor accepts only the 14 standard fonts. The mapped-text engine refused tagged documents outright, and Word adds tags by default. Changes:

- **Edit text fallback.** When the built-in editor refuses a clicked text object and the companion engine is installed, the same on-page editor opens through a new single-call `FindText` companion operation. It matches the clicked object's text and its occurrence order among page-level runs, so there is no paging through `InspectText`. Commit builds the isolated, natively validated candidate (`PreviewStructuredTextAsync`) and applies it as one undoable checkpoint. There is no separate candidate-review step; the committed page is shown at once and Undo restores it.
- **Wider text.** A replacement wider than the original run is held back with an explanation. **Ctrl+Enter** applies it anyway, because it may overlap following text. Characters missing from an embedded subset font are refused with a plain-language explanation, and the draft is kept.
- **Tagged documents** (`StructTreeRoot` or `MarkInfo /Marked`) are now accepted by `InspectText`/`EditText`/`FindText` for **page-level runs only**. Nested-form text in tagged documents stays refused, because structure elements can reference the form XObjects that nested edits clone. After a tagged edit, the reopened candidate must still have its structure tree and Marked flag, and its page's ordered `BMC`/`BDC`/`EMC` operators and operands must be identical to the original's. Otherwise the edit is refused.
