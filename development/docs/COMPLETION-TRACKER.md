## Remaining implementation, in priority order

1. **Complete direct editing as a user workflow.** Meet the direct-click acceptance above. Add exact nested text hit mapping only with geometry evidence. Broaden existing-text editing only with a defined supported font/encoding/transform set, per-object preview, collision/overflow rejection, and native render comparisons; test undo, recovery and save/reopen. Preserve the distinction between replacing existing text, adding new text, and permanent redaction.
2. **Finish markup and annotation workflows.** Current source supports selected highlight/underline/strikeout rectangles, sticky notes, bounded existing note updates/deletions, and line/rectangle/ellipse annotations with coordinate entry or rendered-page bounds placement. Accept physical page placement and implement remaining requested text boxes, arrows/pen as scoped, and safe movement/restyling only where native appearance and hit geometry are preserved. For every type, prove correct visible output, independent subtype/geometry, protected locked/link/widget refusal, undo/recovery/save/reopen, and unchanged source. Markup must never be presented as redaction.
3. **Expand existing-form support deliberately.** The narrow text and checkbox source paths do not establish support for radio groups, choice fields, multiple widgets, JavaScript, XFA, field authoring or custom font appearances. For each added type, define supported field/widget/action/appearance rules, reject ambiguous or unsafe cases before mutation, verify output independently and through PDFium render, and prove undo/recovery/save/reopen. Keep unsupported fields visible as unsupported rather than silently editable.
4. **Broaden OCR only through eligible-page proofs.** Current multipage source still refuses mixed-content documents and structures outside its strict scan-only subset. Establish accuracy and language disclosures, bounded memory/time behavior, per-page eligibility, cancellation at preflight/recognition/publication, exact visible-pixel preservation, metadata/geometry preservation, searchable output on every page, and source/session preservation on every refusal. Do not claim general or mixed-document OCR until those cases have an independently verified design.
5. **Extend redaction compatibility without weakening permanence checks.** The accepted subset removes selected visible/invisible text and supported image pixels and removes touched vector paths whole. Broader fonts, forms, annotations, links, layers, tags, Form XObjects, shared images, marked content and rotated/cropped pages remain refused. Each newly supported structure needs an independent raw-object/stream review and rendered proof that target content is absent while unrelated content survives. Retain original files and recovery copies; describe this as verified content removal, not disk erasure.
6. **Finish printing fidelity and bounded operation evidence.** Current raster printing is restricted to ten pages, approximately 150 DPI and two million pixels per page; text/vector and broad widget fidelity are not generally verified. Compare intended output across representative text, image, annotation and supported form content; confirm page range, rotation, scaling, cancellation and printer dialog behavior on physical Windows hardware. Do not imply print-production/preflight support.
