## October 21 on-page editing update

**Edit** (command bar) shows page tools that work directly on the rendered page: click existing text to retype it in place, click to add text or a sticky note, drag to highlight/underline/strike out text, and drag to draw pen strokes, lines, arrows, rectangles, ellipses or a text box. Enter applies, Esc cancels, and Ctrl+Z undoes. The same engine limits apply: supported top-level text objects only, new text in basic Latin at 18 pt Helvetica, and annotations on unrotated, zero-origin pages only. Rotated-page text editing opens the existing editor window. Coordinate entry remains under Properties → Precise placement and lists. Physical pointer input is not yet accepted; see BUILD-STATUS.md.

Edit text also works on document text in embedded or subset fonts, such as Word exports, including tagged PDFs, through the companion engine. It keeps the PDF's own font. The limits are:
- Page-level text only in tagged PDFs.
- Only characters the embedded font contains.
- No reflow; wider text needs Ctrl+Enter.
- Signed and encrypted documents are refused.

## Working workflows

- **Fill existing form…** lists current-page fields and supports one unique plain-text AcroForm field with one unrotated widget, a proven standard Type1 font/encoding and glyphs, plus one unique single-checkbox field with one unrotated widget and explicit valid on/off appearances. The adapter checks inherited field properties, actions, font encoding and fit, validates checkbox states/appearances, and independently reopens the saved value. Read-only/password/rich-text/multiline/calculated text fields, ambiguous names, XFA, custom text fonts, read-only or rotated checkboxes, radio/pushbuttons, choices and populated signatures are refused. Field authoring and JavaScript are not implemented. Current checkbox evidence: 31 session checks and 25 UI checks. Accepted filling supports undo/redo, recovery and save/reopen. Empty signature fields still trigger the existing explicit copy-consent gate.
- **Recognize scan text…** adds a local English searchable layer to an eligible scan-only PDF of 1–50 pages. Every page must contain exactly one full-page opaque RGB/grayscale scan image at an eligible native resolution; each image is capped at 12 million pixels and the document total at 24 million pixels. It preflights every page, refuses a document if any page contains existing/mixed content or unsupported structures, and verifies decoded image pixels, placement, page geometry, PDF Info metadata and exact per-page PDFium render identity. The expanded current integration proof passed 20 session and 13 companion checks, including multipage text, undo/recovery/save/reopen, refusal and source-preservation cases. The helper's two-page proof also passed. The 50-page limit does not guarantee completion within the three-minute advanced-worker budget; no maximum-size throughput claim is made. Check recognition with Search or text selection; accuracy is not guaranteed. No document is uploaded.
- **Create signed copy…** uses a local PFX/P12 private key and a currently valid RSA certificate of at least 2048 bits. The new unsigned/unencrypted input copy is signed incrementally, preserving its byte prefix, then checked cryptographically and reopened with PDFium before create-only publication. Passwords travel through stdin, are not logged or stored in preferences, and the UI password field is cleared. The original tab's edit/save state remains unchanged; the resulting copy opens separately. This does not add a drawn mark, establish certificate trust/revocation/trusted time, support co-signing or use the Windows certificate store.
- **Permanent redaction…** prepares and renders an actual private candidate for a manually entered current-page rectangle measured from the top-left in PDF points. Review confirmation is required before exporting the exact candidate to a new file. Selected visible/invisible text and supported image pixels are removed; a vector path touched by the rectangle is removed in full. Unrelated text and vectors remain native objects; there is no flattening fallback. Standard metadata and XMP are removed and document IDs regenerated. This restricted version refuses forms/signatures, tags, layers, bookmarks, attachments, annotations/links, Form XObjects, marked content, nonstandard fonts, shared/complex images and rotated/cropped pages. The source PDF, other source copies and recovery history are retained; this is not disk erasure. The open session remains unchanged.
- Open PDF files using the picker, recent list or drag/drop; use independent document tabs. View pages, thumbnails, bookmarks, search results, selectable text, page navigation and zoom/fit modes.
- Use Save As to preserve original PDFs. Save, Undo/Redo, dirty close, backups and recovery use the existing validated document checkpoints. Signed-document changes require explicit copy consent and invalidate signatures on that copy; the app does not validate certificate trust.
- Choose **Edit existing text** for the current page to replace a supported top-level text object. The existing-text helper also exposes **Mapped existing text** for a specific text run, including nested/shared form content, with a rendered candidate preview before Apply. The mapped path uses proven font mappings and horizontal metrics for supported Type1, TrueType and Type0 fonts; CID fonts require Identity-H and ToUnicode. Missing/ambiguous glyphs or widths, ActualText/tagged content, signed/encrypted PDFs, clipping text render modes, zero/reverse advance, stale selection, and unsupported structures are rejected. Inspection is bounded to 128 MiB input, 2,000 expanded forms/text runs, 200,000 content operations, and 4,000 characters per run (with a separate transport limit); pages are browsed in small batches. A wider replacement requires explicit preview review. The 22-check current session proof covered embedded/subset-font mapping, nested shared forms, candidate preview, apply, undo/redo, recovery, save/reopen and missing-subset-glyph refusal. This modifies existing text rather than covering it, but does not reflow paragraphs or perform secure redaction. The direct-edit route's focused UI proof passed text/image preselection, blank-space handling, signed-consent re-extraction and source-preservation checks by invoking the actual route with test coordinates. Physical mouse selection, zoom/rotation and live desktop interaction remain unverified; direct click targets only supported bounded top-level objects.
- **Add text** adds new basic-Latin content at entered PDF-point coordinates on the current page. It is separate from existing-text replacement. **Rotate** also targets the current page.
- **Annotations…** supports highlight, underline and strikeout over rectangles selected from page text or entered in PDF points. It accepts 1–100 rectangles per operation and supports Undo/Redo and save/reopen. **Sticky note** adds a Unicode/multiline comment on an unrotated page. **Add drawing…** adds a line or bounded arrow (native Ink strokes), rectangle (Square), or ellipse (Circle) annotation by entering PDF-point bounds or using Place on page to select a reviewed outline on an unrotated rendered preview. The bounds return to editable coordinates; Add drawing performs the separate commit. Lines and arrows join the bottom-left/top-right bounds corners. The latest worker run passes 51 drawing checks with independent pypdf/MuPDF evidence, including render, bounds refusal, undo, save/reopen and protected deletion cases; independent print verification passed four checks after setting the print flag on new notes, markup and drawings. The focused drawing UI proof passes 20 checks, including a visual repeat at the corrected 620-pixel default height. **Existing sticky notes** reads current-page comments; oversized/unavailable contents are explicitly marked. **Edit or delete existing annotations…** updates one supported note comment (up to 4,000 characters) or removes one unlocked sticky note, highlight, underline, strikeout, line, arrow, rectangle or ellipse, with undo/redo, recovery and save/reopen. Locked/read-only/content-locked annotations, links and widgets are protected; documents containing linked annotation popups/replies are refused for management. Management is bounded to 1,000 pages and 10,000 annotations; lists show the first 1,000 annotations with bounded text. Physical acceptance of preview-based placement, freehand pen, arbitrary-direction arrows, text boxes, movement/restyling and broader annotation-type management remain incomplete. Annotations do not redact page content.
- **Combine PDFs** accepts unsigned, unencrypted PDFs. Add files, inspect names/paths and page counts, use Move up/down or Remove, then choose a new output filename. Per-file page ranges support blank for all pages or entries such as `1,3-5`, selected-page totals and file-specific validation. Range edits are locked during a job. Output is reopened and checked before publication; existing files and input files are never replaced.
- **Text preview** shows the rendered page and an isolated candidate render for valid proposed replacement text. The candidate is not committed until Apply; stale requests are canceled without changing the current document. This remains restricted to the supported existing-text subset above.
- **Images** can add a supported single-frame raster image, replace or remove a selected top-level image, and adjust its PDF-point rectangle. Inputs and geometry are bounded; unsupported or malformed images are rejected. This does not provide arbitrary nested-image editing.
- **Page organization** can move pages, duplicate the selected page immediately after itself, delete one selected page, insert a blank page, and import an ordered source-page range such as `1,3-5` from a separate eligible PDF immediately after the selected page; blank imports every page. Import is limited to 5,000 source pages per action and 50,000 resulting document pages. Undo, subset order, save/reopen, geometry, source hashes and unsafe-source refusal are verified. Encrypted, signed, form-bearing, tagged, bookmarked, named-destination, attachment-bearing, labeled, annotated or marked-content source PDFs may be refused. The final page cannot be deleted. Navigation targets are validated before and after a native operation and again on the candidate checkpoint. Operations that cannot preserve a numeric ordinal destination or custom page labels are rejected with rollback. Extraction writes selected pages, in the requested order, to one new PDF (up to 5,000 pages); split writes one PDF per page to a new folder (up to 50,000 pages). Independent pypdf checks reopen extraction and split outputs and compare text, requested order, page boxes, rotation and source hash. Both refuse unsupported source documents, never replace existing output and preserve the open source. Page-picker and output-folder dialogs still need physical interaction acceptance.
- **Print** uses the native printer and range picker with an explicit raster-output confirmation. Jobs are limited to ten pages, approximately 150 DPI and at most two million pixels per page. The pinned PDFium form-fill renderer displays the tested AcroForm widget value in viewer and raster-print output before and after save/reopen; this is fixture-level appearance evidence, not general form acceptance. Text/vector fidelity and broader form appearance may differ. Physical printer acceptance remains pending. Use a shorter page range for larger documents.
- The shell has labeled commands, larger targets, system/light/dark theme selection, high-contrast system colors, keyboard focus, Ctrl+F and common save/tab shortcuts. Native title-bar behavior is retained.

## Combine and recovery limits

Combine imports page content. Document-level bookmarks, forms, attachments, labels, metadata and digital signatures are not promised to survive; signed/encrypted inputs are rejected. Cancelling terminates its isolated worker. If cancellation occurs during final publication, check the output path; abrupt termination can leave an unreferenced hidden temporary candidate beside the chosen destination. Original inputs are preserved. Native worker requests have a thirty-second timeout; advanced companion requests have a separate three-minute budget, which is not a completion guarantee for a maximum-size OCR job.

Uncommitted text drafts are not recovery checkpoints. Undo history has no quota. Power-loss, cloud-sync and network-share behavior have not been certified. The tested AcroForm widget value renders through the pinned form-fill path; broader widget/form fidelity remains unverified and matters for raster printing.
